# 포우데이 · Pawday

반려동물과 보호자의 좋은 하루를 위한 **한국어 가상 서비스 웹앱**입니다. 외부 이미지·폰트·API 없이 로컬 SVG 일러스트와 CSS로 따뜻한 반응형 화면을 구성했습니다. 서비스, 가격, 사용자와 반려동물은 모두 가상 예시입니다. 실제 예약·결제·로그인·서버 DB는 없습니다.

## 실행

Node.js 20.19+ 또는 22.12+와 npm이 필요합니다. 이 작업은 Node.js 24에서 확인했습니다.

```sh
npm ci
npm run dev
```

개발 서버는 `http://localhost:5173`에서 실행됩니다. 클라우드 환경에서는 5173 포트를 미리보기/포트 전달 기능으로 열어 주세요. 이 명령은 서버를 모든 인터페이스에 바인딩합니다. 원치 않는 외부 공개는 설정하지 마세요. 개발 종료는 Ctrl+C입니다.

기본 npm 캐시 경로를 쓸 수 없는 클라우드 환경에서는 `npm ci --cache /tmp/pawday-npm-cache`를 사용하세요.

```sh
npm run build
npm run preview
```

빌드 결과는 `dist/`, 빌드 미리보기는 4173 포트입니다. 운영 배포는 수행하지 않았습니다.

## 체험 흐름

1. 홈에서 서비스 찾기로 이동하고 돌봄·산책·미용을 필터링하거나 상세를 엽니다.
2. ‘우리 아이’에서 기본 프로필 보미를 수정하거나 가상 프로필을 추가합니다. 실제 개인정보는 입력하지 마세요.
3. 서비스를 예약하면서 프로필·날짜·시간을 선택합니다. 현재 시간 이전 예약과 같은 아이의 같은 날 중복 예약은 막습니다.
4. 예약 내역에서 취소하거나 새로고침하여 저장 결과를 확인합니다. 취소는 확인 창을 거치고 내역을 남깁니다.
5. 상단 ‘하리 · 데모 / 주니 · 데모’ 선택으로 사용자별 데이터를 확인합니다. 주니는 빈 상태부터 시작합니다. 새로고침하면 선택 사용자는 하리로 돌아오지만 두 사용자의 데이터는 유지됩니다.
6. 하단 초기화는 확인 후 두 사용자 데이터를 모두 초기 상태로 되돌립니다.

## 구조와 선택

- Vite + React 19 + TypeScript: 작고 빠른 SPA 개발과 엄격한 타입 검사를 위한 구성.
- `src/main.tsx`: 페이지 상태, 공통 레이아웃, 서비스 탐색, 네이티브 `<dialog>` 기반 상세/프로필/예약/취소.
- `src/model.ts`: 도메인 타입, 예시 카탈로그, 입력 검증, 버전별 저장 데이터 검증.
- `src/style.css`: 모바일·데스크톱 스타일, 포커스 표시, 모션 감소 설정.
- `src/model.test.ts`: 데이터 왕복·오염·입력·중복 예약 단위 테스트.
- `tests/demo.spec.ts`: Chromium 데스크톱/모바일 핵심 흐름 테스트.
- `AGENTS.md`: 후속 개발 지침.

단순한 첫 버전이라 서버·라우터·전역 상태 라이브러리는 추가하지 않았습니다. 페이지는 클라이언트 상태로 전환되며 새로고침하면 홈으로 돌아갑니다. 브라우저 뒤로가기/딥 링크는 후속 범위입니다.

## 검증

```sh
npm run lint
npm run typecheck
npm test
npm run build
# 최초 1회 Chromium 설치
PLAYWRIGHT_BROWSERS_PATH=/tmp/pawday-browsers npx playwright install chromium
PLAYWRIGHT_BROWSERS_PATH=/tmp/pawday-browsers npm run test:e2e
```

E2E는 개발 서버를 자동 시작하고 1440×1000 및 390×844 화면에서 프로필 등록·수정, 서비스 필터·상세, 예약, 취소 확인, 사용자 분리, 새로고침 유지, 빈 상태, 중복 예약 오류, Escape 닫기, 손상 데이터 복구를 검증합니다. 실행 중 스크린샷은 `test-results/`에 생성되며 git에서 제외됩니다. 브라우저 설치에는 네트워크가 필요합니다.

## 저장 방식과 한계

`localStorage`의 `pawday.demo.v1` 키에 버전 1 JSON을 저장합니다. 저장 정보는 이 브라우저/출처에서만 유지되고 브라우저 데이터 삭제·시크릿 모드 종료 시 사라질 수 있습니다. 장치 간 동기화, 서버 백업, 암호화, 인증과 권한 제어는 없습니다. 사용자 전환은 데모 UI이며 보안 경계가 아닙니다. 같은 출처의 스크립트와 사용자는 데이터를 읽고 수정할 수 있습니다.

손상된 데이터는 경고하고 메모리 데모로 시작하며, 사용자가 초기화하기 전 자동으로 덮어쓰지 않습니다. 저장 거부/용량 부족은 경고하며 화면 내 변경은 유지합니다. 여러 탭의 동시 수정은 충돌 처리되지 않고 마지막 저장이 우선합니다. 시간은 브라우저의 현지 시간을 사용합니다. 실제 재고·영업일·인력·서비스 적합성·소요 시간에 따른 겹침 검사는 없습니다.

## 운영 전 후속 작업

- 서버 기반 로그인/세션, 안전한 쿠키, CSRF 대응, 계정별 권한 검증과 서버 측 입력 검증.
- 운영 DB 스키마·마이그레이션·트랜잭션 및 중복 예약 방지, 서비스별 실제 가능 시간·시간대·동시성 처리.
- 개인정보 최소 수집, 동의·보관·삭제 정책, 암호화·접근 통제·백업·감사 기록.
- HTTPS, CSP 등 보안 헤더, 요청 제한, 의존성 보안 검토, 오류 모니터링 및 접근성 보조공학 수동 점검.
- 실제 업체/가격/자격 검증과 취소 정책. 결제는 별도 요구사항 확정 후 안전한 결제 제공자를 통합.

현재 버전을 운영 서비스로 사용하지 마세요. 코드에 자격증명이나 비밀값을 넣지 않습니다.

이 클라우드 환경에는 Chromium이 미리 설치되어 있어 다운로드 없이 다음 명령으로 실행할 수 있습니다.

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e
```

소스 포맷 정리는 `npm run format`으로 실행합니다.
